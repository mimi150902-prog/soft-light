# Технічне завдання

## Назва проєкту
Soft Light — вебзастосунок фотостудії для перегляду фотозалів, перевірки доступного часу та онлайн-бронювання.

## Проблема
Користувачам необхідно зручно переглядати інформацію про фотозали та доступний час, а також швидко оформлювати бронювання без додаткового звернення до адміністрації.

## Мета та цільова аудиторія
Мета проєкту — створити зручний вебзастосунок для перегляду фотозалів та онлайн-бронювання.

Цільова аудиторія:
- фотографи;
- моделі;
- клієнти фотостудії.

## Ролі користувачів
- **Гість** — перегляд фотозалів та доступної інформації.
- **Користувач** — перегляд фотозалів, вибір дати й часу та оформлення бронювання.
- **Адміністратор** — керування фотозалами, бронюваннями та користувачами.

## Основні функції
- перегляд фотозалів;
- перегляд фотографій та характеристик залів;
- перегляд доступного часу;
- реєстрація та авторизація;
- вибір дати та часу;
- оформлення бронювання;
- введення контактних даних;
- внесення передоплати;
- перегляд власних бронювань;
- скасування бронювання;
- керування фотозалами адміністратором;
- керування бронюваннями адміністратором;
- керування користувачами адміністратором.

## Функціональні вимоги
1. Система повинна надавати можливість переглядати список фотозалів.
2. Система повинна відображати фотографії, опис та характеристики фотозалів.
3. Система повинна відображати доступні дату та час для бронювання.
4. Гість повинен мати можливість переглядати інформацію про фотозали.
5. Користувач повинен мати можливість зареєструватися та авторизуватися.
6. Користувач повинен мати можливість вибрати фотозал, дату та час.
7. Система повинна дозволяти оформити бронювання.
8. Під час бронювання система повинна приймати контактні дані користувача.
9. Система повинна підтримувати внесення передоплати.
10. Користувач повинен мати можливість переглядати власні бронювання.
11. Адміністратор повинен мати можливість керувати фотозалами.
12. Адміністратор повинен мати можливість переглядати та змінювати бронювання.
13. Адміністратор повинен мати можливість керувати користувачами.

## Нефункціональні вимоги
- сторінки вебзастосунку повинні коректно відображатися на комп'ютерах та мобільних пристроях;
- інтерфейс повинен бути зрозумілим та зручним для користувача;
- основні сторінки повинні завантажуватися не довше 3 секунд за нормального підключення до мережі;
- передача даних повинна здійснюватися через HTTPS;
- доступ до адміністративної панелі повинен бути захищений авторизацією;
- система повинна забезпечувати збереження даних користувачів та бронювань.

## Обмеження проєкту
- вебзастосунок розробляється як навчальний проєкт;
- на першому етапі система працює з обмеженою кількістю фотозалів;
- розробка та тестування можуть виконуватися локально та на хостингу;
- функціональність платіжної системи може бути представлена у спрощеному вигляді.

## Критерії готовності першої версії
Перша версія вважається готовою, якщо:

- реалізована головна сторінка;
- реалізований перегляд фотозалів;
- реалізована сторінка окремого фотозалу;
- реалізована реєстрація та авторизація;
- реалізоване бронювання фотозалу;
- реалізований перегляд власних бронювань;
- реалізована адміністративна панель;
- основні функції перевірені та працюють без критичних помилок.
